# Fresh causal temporal v2 forecast comparison

Status: fresh v2 training and final2 validation completed. This is development evidence only. It does not modify or replace the frozen spatial protocol.

## Question and scope

Compare persistence, linear extrapolation, and the current `linear_velocity_residual_v2` GRU on the coupled validation trajectories. The current truth matrix is also reported as an unavailable current-CSI reference. All four use the same memory-free `pair` search, all-OFF initial state, medium search configuration, and an all-OFF RZF precoder computed from the immediately preceding observation. The forecast and controller belief use only the four prior matrices; the oracle is labeled noncausal. Because the pair search is heuristic, the current-CSI reference is not a guaranteed per-frame upper bound on truth rate.

The v2 GRU was trained for seeds 7, 19, and 43 using examples selected from the existing train split and `scripts/train_coupled.py --kind gru --epochs 25`. Train-only mean/scale and the active-link mask are recorded with the checkpoints. No legacy GRU checkpoint is loaded. No pilot or test samples are selected for training or evaluation. The dataset container may include those splits; this statement concerns the samples selected by the training and validation code.

## Validation accounting

The benchmark requires exactly 36 frames from the three validation trajectories, with steps at least four and four contiguous preceding observations from the same trajectory. It records 5, 10, and 50 ms budgets for three search seeds. For every method/seed/frame/budget it checks that the stale-reference precoder hash is identical and that the search receives an empty memory tuple.

Timed action latency includes stale-reference network/RZF construction, history slicing, forecast and passive projection, belief-network setup, and pair search. Exact current-truth action rate and the cached-versus-full belief-score consistency check are computed after the timer stops. Results are paired by seed, frame, and budget; summaries must report misses, latency, evaluation counts, rates, and per-trajectory means. With only three validation trajectories, aggregate differences are exploratory.

## Commands

Training uses a fresh run root containing a copy of the verified physics gate:

```bash
for seed in 7 19 43; do
  PYTHONPATH="$PWD/src" python scripts/train_coupled.py \
    --kind gru --seed "$seed" --epochs 25 --device cuda \
    --run outputs/runs/temporal_v2_improvement_20261106
done
```

Run the complete validation grid on a quiet pinned CPU core:

```bash
PYTHONPATH="$PWD/src" python scripts/benchmark_temporal_forecast.py \
  --run outputs/runs/temporal_v2_improvement_20261106 \
  --data data/processed/coupled_wire_v1/dataset.npz \
  --budgets-ms 5 10 50 --seeds 7 19 43 \
  --expected-frames 36 --search-config medium
```

The benchmark writes JSONL rows and a metadata sidecar under the fresh run root. Both include input, checkpoint, scaling, source-code, gate, and search-config hashes. Never overwrite a prior result; choose a new run root for a rerun.

## Results

The fresh run is under `outputs/runs/temporal_v2_improvement_20261106/`. It used dataset SHA-256 `08e2c39ef25547fd05ca60ccd7aaa3110889d743e0751ecd12ef85fe5dbea39d`, train-only scaling (retrospectively recomputed from `split==train` and exactly matched all three saved scaling arrays), and v2 GRUs for seeds 7, 19, and 43. Checkpoint SHA-256 values are recorded in `migration_manifest.json` and the validation metadata. No pilot or test samples were selected for training or evaluation.

GRU forecasts reduce MSE versus linear extrapolation, but their paired truth-rate advantage is small and inconsistent over only three trajectories: −0.0132, +0.0274, and +0.0515 bits/s/Hz at 5, 10, and 50 ms. GRU is therefore not established as a useful online improvement by this validation. The comparison is exploratory, has three independent trajectories, and is not held-out evidence.
