## ME-GA review

The reimplementation keeps paper facts distinct from assumptions. `MEGAParams` records `Gamma=100`, `V=100`, `W=3`, the listed parameter ranges, and an explicit `stagnation_delta=None`; binary tournament selection, crossover, mutation, memory capacity, and replacement choices are labeled assumptions in the implementation and the method table. The paper specifies a stagnation form but publishes no delta. Defaulting to the stated V cap avoids silently selecting a threshold that could stop before the memory operators have a chance to run. A caller can set an absolute delta, and the documentation now marks the earlier relative-delta smoke as superseded. See [me_ga.py](/home/parasite/Work/conference/atom-wise-ris/src/atomwise_ris/optimization/me_ga.py:35) and [me-ga-reimplementation.md](/home/parasite/Work/conference/atom-wise-ris/docs/me-ga-reimplementation.md:65).

Two equation ambiguities/deviations remain material and are stated in the implementation: Eq. 15's TeX expression uses a history-wide best although the surrounding prose calls it the v-th iteration best; default `theta_series='iteration'` follows the prose, while `running` retains the literal TeX variant. The literal negative branch of Eq. 17 can leave the probability range or divide by zero; the default magnitude-normalized rule is a documented deviation, with alternatives exposed. These choices are defensible for an honest reimplementation, but they are not evidence of an exact reproduction. No source correction is requested from this review.

The benchmark wiring preserves trajectory-local memory: specular runs call `Memory.enter(trajectory)` and the coupled loop replaces ME-GA memory on trajectory change. ME-GA's internal Psi update is not overwritten by benchmark post-processing, and it is included in measured controller time. Candidate rescores use the objective evaluator and are included in the evaluation accounting; the later full-action consistency and truth-rate calculations are benchmark verification outside controller search. `me_ga_paper` passes no deadline to the optimizer, reports true elapsed runtime, and marks deadline applicability false. Extra ME-GA methods require explicit output paths, are spatial-only in coupled mode, and are refused on test splits. These conclusions are based on [benchmark.py](/home/parasite/Work/conference/atom-wise-ris/scripts/benchmark.py:163), [benchmark_coupled.py](/home/parasite/Work/conference/atom-wise-ris/scripts/benchmark_coupled.py:133), and the method dispatch in [me_ga.py](/home/parasite/Work/conference/atom-wise-ris/src/atomwise_ris/optimization/me_ga.py:373).

The ME-GA source changes fall under the v1 frozen-code hash glob. They invalidate direct comparison to an earlier v1 source freeze unless that run is revalidated with the exact code snapshot. The C1 action audit below uses the byte-hashed, already frozen gate-fix validation actions and checks the current physical evaluator files against their captured source hashes; it does not use ME-GA or modify a controller result.

## C1 action-mesh audit

Added [audit_v2_mesh.py](/home/parasite/Work/conference/atom-wise-ris/scripts/audit_v2_mesh.py) and [test_v2_mesh_audit.py](/home/parasite/Work/conference/atom-wise-ris/tests/test_v2_mesh_audit.py). The audit accepts only the locked 50 ms spatial-validation grid. It validates the source JSONL against the exact selection hash, protocol and sidecar identity, complete method × seed × budget × frame coverage, and the 48 declared validation frame identities. It checks the network, precoding, and NEC source hashes against the captured freeze, verifies the coarse data and physics-gate hashes, and requires the fine scenario to bind to the source scenario. It then rescales only the fixed returned 64-bit actions; it never optimizes or retunes them.

The primary comparison evaluates each action on coarse and 161-segment impedance matrices with the same frame-specific coarse all-OFF RZF precoder. A separate sensitivity applies one common 161-segment all-OFF RZF precoder to every method's action on each frame. The report contains per-method rate shifts, ON-count associations, paired method-order reversals, and trajectory-cluster summaries. The validation set has only three independent trajectories, so resampling intervals and correlations are descriptive and weakly determined. The 161-segment matrix is not established as converged; no population-fidelity statement or universal numerical tolerance is justified. This validation-only rescore does not fulfill the protocol's separate conditional held-out test audit. That v1 contract predeclares 81 versus 161 segments and a 0.015 bit/s/Hz criterion for that test-action audit. Further mesh convergence work would require a separate predeclared design; 241 segments must not be assumed more accurate without evidence.
